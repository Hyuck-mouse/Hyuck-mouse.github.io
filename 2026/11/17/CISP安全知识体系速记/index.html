CISP 安全知识体系速记

Created2026-11-17|Updated2026-11-17|安全理论
|Post Views:

前面几篇都是 Web 实战技术，这篇换个角度——整理 CISP（注册信息安全专业人员）备考中梳理的理论知识：安全模型、身份认证、访问控制、风险评估、等级保护等。这些概念看似”偏文”，但理解它们对建立完整的安全世界观很有帮助，也是很多offer/认证的必考内容。

一、安全服务与 OSI 模型

网络层提供五类安全服务：保密性、身份鉴别、完整性、抗抵赖、访问控制。

OSI 七层模型与对应协议：

层级 名称 主要功能
7 应用层 应用程序接口（HTTP、FTP、SMTP）
6 表示层 数据格式转换、加解密
5 会话层 建立、维护、终止会话
4 传输层 端到端通信、可靠传输（TCP、UDP）
3 网络层 路由选择、逻辑寻址（IP）
2 数据链路层 物理地址（MAC）、帧传输
1 物理层 电信号传输

IP 属于网络层，TCP 属于传输层。TCP 可靠但机制复杂，传输效率低于 UDP。

二、安全框架与模型

IATF

IATF（Information Assurance Technical Framework）是指导信息安全整体建设的技术框架，强调”纵深防御、多层防护“。它不专门针对源代码审核，而是提供整个信息系统生命周期的安全设计与实施指导。

STRIDE 威胁建模

微软提出的威胁建模方法，六个字母对应六类威胁：

字母 威胁类型 含义
S Spoofing 冒充、伪装身份
T Tampering 篡改数据
R Repudiation 抵赖（否认行为）
I Information Disclosure 信息泄露
D Denial of Service 拒绝服务
E Elevation of Privilege 权限提升

常用安全模型

  • PDR：保护 → 检测 → 响应
  • PPDR：策略 → 保护 → 检测 → 响应
  • PDCA：计划 → 执行 → 检查 → 改进（持续改进，Act）
  • 信息系统安全保障模型：生命周期 + 安全特征 + 保障要素

SSE-CMM 与 ISMS

  • SSE-CMM：能力成熟度模型，面向工程过程质量控制；基本实施（BP）是安全工程的最小单元。
  • ISMS（信息安全管理体系）：文档结构分 4 层金字塔——一方针策略、二制度规范、三手册流程、四表单记录。

三、身份认证

四种鉴别方式（重点区分”所知”与”所有”）：

类别 说明 例子
所知 用户知道的东西 密码、PIN 码、口令、验证码
所有 用户持有的设备 智能卡、USB Key、手机、令牌
特征 生物特征 指纹、人脸、虹膜、声纹
行为 行为习惯 打字节奏、鼠标轨迹、步态

⚠️ 易错点：令牌是基于”所有”的鉴别方式，口令是基于”所知”。

电子签名：基于密码学（公钥 PKI）的数字认证手段，用”数字证书 + 数字签名算法”实现，具备不可伪造性、不可否认性、完整性。注意：电子签名不可与认证服务提供者共有。

四、访问控制

  • ACL（访问控制表）：以客体为中心 → “这个文件谁能访问？”
  • CL（能力表）：以主体为中心 → “这个人能干什么？”

Linux 文件权限：

文件类型标识：- 普通文件、d 目录、l 软链接、c 字符设备、b 块设备、p 管道、s 套接字。

权限位：r（读=4）、w（写=2）、x（执行=1）；用户类别 u(user)、g(group)、o(others)、a(all)。

各字段含义依次是：文件类型、所有者权限、所属组权限、其他用户权限、硬链接数、所有者、所属组、大小、修改时间、文件名。

常见操作：

  • netstat 查看本机端口；
  • mmc 打开 Windows 管理控制台；
  • regedit 打开注册表；
  • Apache 目录访问控制配置文件：httpd.conf。

五、风险评估

风险三要素：威胁（Threat）、脆弱性（Vulnerability）、影响（Impact）。

风险计算公式：

  • A：资产（Asset）
  • T：威胁（Threat）
  • V：脆弱性（Vulnerability）
  • L：可能性——威胁利用脆弱性的概率
  • F：影响——取决于资产价值和脆弱性严重程度

原则：

  • 安全策略是宏观原则性要求，不包含具体细节。
  • 安全产品选择属于”风险处理”环节。
  • 监测控制设备在有了充分预防控制后，是可选而非必选。
  • 2004 年 1 月起，国内申报信息安全国家标准计划项目必须经 TC260（全国信息安全标准化技术委员会）。

六、安全测试技术

测试类型 说明
源代码审核 静态分析，发现缓冲区溢出、SQL 注入、硬编码密码等；分工审核与工具审核（SonarQube、Fortify、Checkmarx）
模糊测试 向程序输入大量随机/异常数据，观察是否崩溃
渗透测试 模拟黑客攻击，从外部发现配置、权限、访问控制问题
软件功能测试 验证功能是否按需求正常工作

软件安全测试应根据实际情况选择和组合测试措施，不要求每一项都测。

七、等级保护与相关规范

  • 等级保护三级系统：一年测评一次；
  • 四级系统：半年测评一次。
  • SSAM（安全服务评估）：规划 → 准备 → 现场 → 最终。
  • CNCI：以风险为核心，首要任务是降低网络面临的风险。
  • Windows 在 XP SP2 引入”安全中心”概念。

八、拒绝服务攻击

流量型 DoS 攻击：Teardrop 碎片攻击、Land、UDP Flood、Smurf。

九、IPSec 与加密

  • IPSec 在网关中处理。
  • 信息安全标准可以与国际标准相同，也可以不同。

小结

CISP 理论知识的特点是”概念多、易混淆“，复习时要抓住对比记忆：

  • ACL（客体为中心）vs CL（主体为中心）
  • 所知（口令）vs 所有（令牌）
  • 保密性/完整性/可用性 三要素
  • PDR / PPDR / PDCA 各阶段顺序
  • 三级一年一测 / 四级半年一测

把这些高频考点整理成对比表，考前过一遍效率最高。虽然日常做 Web 实战用不到这些，但它们构成了安全从业者的完整知识底座。

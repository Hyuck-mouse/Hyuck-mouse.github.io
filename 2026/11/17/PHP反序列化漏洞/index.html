PHP 反序列化漏洞与 POP 链

Created2026-11-17|Updated2026-11-17|Web安全
|Post Views:

PHP 反序列化漏洞是 CTF Web 的常客。当 unserialize() 处理用户可控数据时，对象的魔术方法会被自动触发，攻击者借此构造 POP 链执行危险操作。本文系统整理序列化基础、魔术方法触发时机、POP 链与字符串逃逸。

一、序列化基础

序列化是把对象转成可存储的字符串，反序列化则还原。几个要点：

  • private、protected 属性序列化后的字段名格式特殊（会带 \0 前缀），手工构造 payload 时注意。
  • 序列化只保存对象的属性，不保存方法。

二、魔术方法与触发时机

反序列化的核心是魔术方法的自动调用。记清每个方法的触发时机，是构造 POP 链的前提。

魔术方法 触发时机
__construct() 对象创建时（new）
__destruct() 对象销毁时 / 反序列化结束后自动触发
__sleep() 执行 serialize() 之前
__wakeup() 反序列化之前触发（unserialize() 时）
__toString() 对象被当作字符串使用时
__invoke() 对象被当作函数调用时
__call() 调用不存在的方法时
__callStatic() 静态调用不存在的方法时
__get() 获取不存在的属性时
__set() 给不存在的属性赋值时
__isset() 对不可访问属性调用 isset() 时
__unset() 对不可访问属性调用 unset() 时
__clone() 对象被克隆时

三、POP 链与 POC 编写

POP（Property-Oriented Programming，面向属性编程）链：当单个魔术方法不能直接达到目标时，通过属性把多个类的方法”串”起来，形成一条从入口（__destruct 等）到危险函数（如 system、file_put_contents）的调用链。

思路：

  1. 找起点：反序列化后会自动触发的方法（常见 __destruct、__wakeup）。
  2. 找终点：能执行命令/读写的危险方法（如 __toString → eval、__invoke → 回调函数）。
  3. 用属性作为”跳板”，让前一个方法调用后一个对象的方法，串成链。
  4. 编写 POC：实例化、赋属性、serialize() 生成 payload。

构造时按需把 private/protected 属性名写成带 \0 的正确格式，否则链断。

四、字符串逃逸

字符串逃逸分减少和增加两类，本质是破坏序列化结构的对称性，让后半段被当作新对象解析。

增加的逃逸：过滤时把某个字符替换成更长的字符串（如 s → xx），导致实际长度 > 声明长度，可以”吃掉”后面的结构，注入新的属性。

减少的逃逸：替换成更短的字符串，使实际长度 < 声明长度，把后续字符”拉”进当前字符串，从而篡改结构。

构造核心：精确计算长度差，让替换后的序列化串在解析时把Payload 部分解释成我们想要的字段。

五、常见绕过点

  • __wakeup() 绕过：序列化字符串中对象属性个数大于实际个数，可跳过 __wakeup()（经典 CVE-2016-7124，PHP < 5.6.25 / 7.0.10）。
  • 正则过滤：preg_match 字符串匹配可用 + 绕过（如 O:+4）。
  • 引用利用：用 & 让两个属性指向同一变量，绕过某些值校验。

小结

反序列化漏洞的解题套路：

  1. 读源码，找 unserialize() 入口和所有类的魔术方法。
  2. 定起点终点：从自动触发的方法出发，找到能落地危险操作的类。
  3. 连 POP 链：用属性把方法串起来。
  4. 写 POC：生成序列化 payload，注意属性可见性与长度。
  5. 遇过滤：考虑 __wakeup 绕过、字符串逃逸、正则绕过。

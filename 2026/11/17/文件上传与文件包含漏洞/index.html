文件上传与文件包含漏洞

Created2026-11-17|Updated2026-11-17|Web安全
|Post Views:

文件上传与文件包含是 Web 渗透中拿到 shell 的两条主要路径。前者解决”如何把木马传上去”，后者解决”如何让上传的东西被当作代码执行”。本文整理常见的上传绕过手法（前端校验、MIME、.htaccess、00 截断、条件竞争、图片马）和文件包含套路（日志包含、伪协议、tar 软链接）。

一、前端 JS 验证绕过

特征：页面源码里写死”只允许 jpg/png/gif”，非允许后缀根本传不上去。这是最弱的校验——只在浏览器端生效。

绕过：把木马后缀改成允许的格式（如 .jpg），用 Burp 抓上传包，把包里的文件名后缀从 jpg 改回 php，再放包。

注意：Burp 里的 Content-Type: image/jpg 保持不变，服务端若只看这个字段就不会拦。

二、MIME 类型绕过

MIME 检测的是文件类型（Content-Type 头），而不只是后缀名，所以单纯改后缀没用——要把 MIME 检测的结果也改成允许的类型。

三、.htaccess 解析漏洞

.htaccess 是 Apache 的目录级配置文件，可做 URL 重写、MIME 配置、访问控制等。作用范围仅当前目录，且文件名不可更改（只有后缀、没有主名）。

思路：让服务器把 .jpg 当成 PHP 解析。

  1. 先随便上传一个 1.php 木马，Burp 抓包。
  2. 把 filename="1.php" 改成 filename=".htaccess"，Content-Type 从 application/x-httpd-php 改成 text/plain。

  2. 再上传木马文件，Burp 抓包把 .php 改成 .jpg，放包，上传成功。

也可用 SetHandler application/x-httpd-php 达到类似效果。

四、00 截断（空字节注入）

原理：在 URL 或文件名中插入空字节（ASCII 0，URL 中写作 %00）。因为 C 风格字符串以 \0 作为结束符，程序读到 %00 就认为字符串结束，后面的内容被”截断”——但被截断的后缀往往正是用来骗过检测的。

绕过：上传木马，Burp 抓包，把后缀改成 php%00.jpg；其他需要提前结束的地方也可加 %00。

⚠️ 限制：目标 PHP 版本需 < 5.3.4，5.3.4 及以上已修复。

五、图片马（文件头检查）

服务端检查文件头（magic number）判断是不是图片时，可以制作”图片马”——把木马拼接到图片末尾。

制作好后上传，Burp 抓包把后缀改成 php，放包即可。（这是最基础的图片马，通常需要配合文件包含才能执行。）

zip 解压场景判断

有些题目上传 zip 后服务端会解压。从前端提示能反推过滤逻辑，例如：

提示 含义
malicious_content_detected 检测到特殊字符
zip_open_failed 文件格式不合法
file_error 容量过大或文件不存在
extract_failed 解压失败

由这些提示可判断服务端会对 zip 解压并做内容检查，从而调整绕过思路。

小结

校验方式 绕过手法
前端 JS 改后缀 + Burp 改包
MIME 改 Content-Type
后缀黑名单 .htaccess、00 截断、双写等
文件头 图片马
上传后删除 条件竞争
无执行权限 文件包含（日志 / SSH 日志）
目录可控 tar 软链接

上传与包含常常组合使用：先想办法把”含有 PHP 代码的文件”传上去，再用文件包含让它被执行。这是 CTF Web 最常见的拿 shell 套路。
